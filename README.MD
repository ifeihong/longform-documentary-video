# 长视频纪录片制作｜Long-form Documentary Video Codex Skill

**长视频纪录片制作**（`longform-documentary-video`）是一项 Codex Skill，用于策划、制作、修订和验收有旁白的中长篇纪录式视频。它适合历史编年、人物传记和知识专题，涵盖脚本分镜、样片与试音、人物和场景素材、可编辑时间线、整片导出及发布物料。

## 新版能力：按参考成片验收样片

指定一部已经认可的纪录片后，Skill 会先对照其开场、地图、人物、转场和声音，从完整播放中提取可观察的制作要求，再为新题材设计代表性样片。每项以样片的实际时间码记录通过、待修或尚未覆盖。

| 对标维度 | 实际检查什么 |
| --- | --- |
| 分镜与运镜 | 解说推进时是否有相应的新视角或细节，同图连续镜头是否突然缩回，换镜是否符合剧情 |
| 地图与合成 | 地图是否随叙述改变视点、范围或历史状态，人物和道具的位置、遮挡与入退是否自然 |
| 人物与文字 | 人物面容、年龄和处境是否一致，标注是否统一，字幕是否重叠或错时 |
| 旁白与配乐 | 声线是否符合已确认的讲述风格，字幕是否贴合实听，音乐是否跟随情节推进、转折与收束 |

若开场无法覆盖关键人物卡、地图进程或复杂合成，可另做一段组合试镜。技术预演用于验证导出链路。风格样片用于确认成片水准，需要展示代表性画面和声音，有临时配音或配乐时应明确注明。详见[成片精度对标与样片验收](references/reference-quality.md)。

## 适用场景与交付物

| 你想做什么 | 可以交付什么 |
| --- | --- |
| 把历史资料或解说稿做成视频 | 时长估算、章节与分镜、样片、旁白和完整视频 |
| 修改已有纪录片 | 按解说定位要改的镜头、修订后的成片及可编辑工程 |
| 验收长视频成片 | 音画同步、黑屏、章节边界、人物状态及素材引用的检查结果 |
| 准备抖音、小红书或视频号发布 | 各平台标题、正文、标签、章节目录及指定比例的封面图 |

## 如何使用

将 `longform-documentary-video` 目录放入 Codex 的技能目录，保留 `SKILL.md`、`references/` 和 `agents/` 的相对结构。技能可用后，在对话中输入：

> 使用 $longform-documentary-video，把我的解说稿制作成一部约 15 分钟的历史纪录片。画幅 16:9，先给我 60 秒样片确认旁白和视觉风格。最终交付 MP4 和可编辑工程。

修订已有成片时，可以直接指定要改的部分：

> 使用 $longform-documentary-video，检查这部历史片的分镜和人物标注。修正画像遮挡地图、背景运镜突然缩回的问题，保留旁白、配乐和总时长。

有已确认的参考成片时，可这样调用：

> 使用 $longform-documentary-video，以《大秦编年史》V14 为制作精度参考，为古罗马专题做一段约 60 秒的有声样片。展示地图推进、人物与场景合成，以及随旁白变化的运镜。附时间码，列出通过、待修和样片尚未覆盖的细节。

上传或指明现有脚本、工程或素材的位置。已确认的声线、风格、画幅和禁止修改的内容也可一并写入任务。

## 制作流程

1. 根据试读语速和停顿估算片长，将脚本拆成章节、叙事节点和镜头。
2. 用样片和短段试音确定画面、声线和配乐关系。
3. 分层制作背景、人物、道具、字幕、动效和声音。让画面变化跟随解说内容，并核对人物身份、服饰和时代背景。
4. 分章导出并验证实际成片，包括完整解码、音轨、帧数、关键镜头和浏览器播放。
5. 按要求打包可编辑工程和发布物料，给出已核验的交付路径。

## 实践案例：《大秦编年史》

这项 Skill 来自一部 **13 分 15.6 秒、1920 × 1080、30 fps** 的历史长片。项目统一了 30 位人物的介绍格式，为昭襄王安排晚年画像，并用同一张脸表现子婴在宫廷反击与投降时的不同状态。合成时，六国地图和已有人物的场景避免再叠画像。

最终 V14 完成全片解码、217 帧编码画面对比和 19 处播放跳转检查，验证原旁白与配乐的 AAC 音频数据保持一致。发布包包含抖音、小红书和视频号文案，以及分别构图的 3:4、4:3 封面。上述数字是本片的验收记录，各项目可按需要确定抽查范围。

## 历史纪录片人物一致性与介绍规范

在分镜阶段建立人物台账，列出每位重要人物的参考脸、年龄或处境版本、出现章节、介绍时间码和史料依据。用台账逐位比对成片，确认介绍覆盖与画面表现。

| 验收项 | 通过条件 |
| --- | --- |
| 重要人物介绍 | 每位重要人物都有可辨认的介绍，能在成片中定位到时间码。次要人物可随事件或纪年带出。 |
| 跨镜头一致性 | 同一人物沿用脸型、五官与识别特征，发色、体态、表情和服饰随年龄及处境调整。 |
| 人物介绍格式 | 统一字体、层级、边距和信息顺序。依次显示称谓、身份、生卒、履历和事迹，只展示实际内容。年代不详时如实标注。 |
| 画面遮挡 | 画像避开背景人物。背景已有清楚可见的人物或人群时，切到专用介绍镜头。地图段禁叠画像。 |
| 出入场 | 人物及介绍文字随解说进退。复查重贴、错标、闪现、退场过早及解说结束后滞留。 |

《大秦编年史》用晚年画像表现昭襄王，用同一张脸的两个版本呈现子婴反击与出降。这套做法也适用于跨越多年、同一人物反复登场的历史编年和人物传记。

### 从分镜到成片的逐镜复查

沿实际时间线检查同图运镜是否突然回缩、背景是否久停或跨时代复用、动效是否对应旁白、道具是否符合时代及摆放逻辑。同时核对字幕重贴、画面角标、旁白停顿、配乐起伏和片尾标题停留及淡黑。问题记录实际时间码，便于回到工程修正并复验。详见[制作规范与逐镜复查](references/production.md)。

## 常见问题

### 需要安装 Remotion 或 FFmpeg 吗？

取决于实际工程。Remotion 和 FFmpeg 是 Skill 提供的本地制作方案，也可以沿用已可用的编辑环境。安装 Skill 即可使用其工作流程，实际生图、合成配音和渲染需要相应工具及运行环境。

### 可以只做分镜、改成片或生成发布文案吗？

可以。说明现有文件和目标即可。做分镜时提供解说稿或主题。修订时优先提供可编辑工程。发布文案和封面则以已定稿的影片为依据。

### AI 人物如何保持同一张脸？

用角色参考图锁定脸部识别特征，再按年代和情节调整发色、表情、服饰和体态。完成后在合成画面中核对身份、年龄、站位和出现时段。

### 怎么确认可编辑工程能用？

核对时间线入口、依赖、字体和引用素材是否齐全，并检查压缩包完整性和工程可打开性。MP4 用于观看，可编辑工程用于后续调整画面、文字、旁白和配乐。
